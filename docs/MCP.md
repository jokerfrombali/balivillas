# MCP The Host Bali: единый слой доступа к данным

Агенту, который будет вести объявления в группах Facebook, нужно знать три вещи:
какие объекты у нас есть, что из них реально свободно и куда сегодня можно
публиковать. Ходить за этим по страницам сайта и календарям глазами — долго и
ненадёжно, поэтому данные отдаёт MCP-сервер.

## Адрес и доступ

    POST https://balivillas.ai/mcp

Сервер разделён надвое. **Без токена** доступна открытая половина, только чтение:
`list_properties`, `get_property`, `check_availability`, `find_available`. Это те же
данные, что видит гость на сайте и любой поисковый робот, поэтому прятать их незачем —
зато ассистент (ChatGPT, Claude) может подключить наш адрес как коннектор и отвечать
человеку по живому календарю. Предел: 60 вызовов в минуту с адреса.

**С токеном** открывается всё остальное: группы Facebook, журнал публикаций и запись.

    Authorization: Bearer <MCP_TOKEN>

Транспорт — MCP over HTTP, тело JSON-RPC 2.0. Отвечаем обычным JSON, без SSE:
все инструменты укладываются в один ответ. Токен лежит в секрете воркера
`MCP_TOKEN`, меняется командой `npx wrangler secret put MCP_TOKEN`. Без токена
ручка отвечает 401, без настроенного секрета — 503.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `list_properties` | открытый · объекты аренды и продажи, фильтры по типу, району, спальням, цене, статусу |
| `get_property` | открытый · полная карточка: описание, фото, условия, ссылка в WhatsApp, костяк объявления |
| `check_availability` | открытый · свободен ли объект на даты, минимальный срок, сумма за период |
| `find_available` | открытый · то же сразу по всем виллам: свободные, занятые и те, кого нет в Hostex |
| `list_facebook_groups` | группы с правилами: интервал, WhatsApp, bump, удалять ли старый пост |
| `upsert_facebook_group` | добавить группу или поправить правила |
| `delete_facebook_group` | убрать группу совсем |
| `get_posting_plan` | куда можно публиковать сегодня, почему нельзя, когда будет можно |
| `save_post_result` | записать результат публикации в журнал |
| `list_posts` | журнал публикаций с фильтрами |
| `delete_post` | убрать ошибочную запись журнала |

## Откуда данные

Объекты — из `data/villas.json` и `data/for-sale.json`, тех же файлов, что читает
сайт. У пяти объектов продажи своих фото нет: это дома, которые мы сдаём, и снимки
подставляются из карточки аренды по `villaId`.

Занятость и цены — из зеркала Hostex в KV, которое обновляет cron каждые полчаса.
Виллы без объекта в Hostex (`hostexLinked: false`) отдаются честно: даты и цена по
запросу, а не выдуманные. Hostex, как и везде на сайте, только на чтение.

Группы и журнал публикаций — в KV: `fb:groups` и `fb:posts`. Журнал подрезается до
2000 записей, он нужен для правила «не чаще раза в N дней» и для отчёта.

## Как считается план публикаций

Для каждой активной группы берём последнюю публикацию из журнала и прибавляем
`intervalDays` из правил. Раньше этого срока `canPost: false` и в `reason` сказано,
сколько ещё ждать. Группа без публикаций — можно. Неизвестное правило хранится как
`null`: пусть агент спросит человека, а не решит за него.

## Подключение

Клиент с поддержкой удалённых MCP-серверов (ChatGPT, Claude, Codex) принимает
адрес и заголовок авторизации. Для клиентов, которые умеют только stdio, ставится
любой http-мост, например `mcp-remote`:

```bash
npx mcp-remote https://balivillas.ai/mcp --header "Authorization: Bearer <MCP_TOKEN>"
```

Проверить живость можно руками:

```bash
curl -s -X POST https://balivillas.ai/mcp \
  -H "authorization: Bearer <MCP_TOKEN>" -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

## Чего пока нет

- Групп в базе нет ни одной: их надо внести через `upsert_facebook_group` вместе с
  правилами каждой группы.
- Панели в HTML нет. Данные уже отдаются, панель поверх них — следующий шаг.
- Публикацию в Facebook сервер не делает и делать не будет: это работа агента в
  браузере. MCP отвечает за данные и журнал.
