# Телеграм-бот сайта: заявки, аналитика, аварии

Бот `@hostbali_bot` — админ вашего чата. Сайт общается с ним **через Cloudflare
Worker**, а не напрямую: токен бота нельзя держать в коде сайта (весь JS видит
любой посетитель через «Просмотр кода» — бота угонят).

```
Гость на сайте  ──POST /api/*──►  Worker (знает токен)  ──►  Telegram
```

## Куда что приходит

| Событие | Топик | Что в сообщении |
|---|---|---|
| Заявка из формы BOOKING | тема 2 (заявки) | номер #0001, время WITA, вилла, даты, ночи, гости, имя, email, телефон, комментарий, ссылка на страницу, город/страна |
| Клик по WhatsApp | тема 2 (заявки) | номер, время, вилла, даты, **точный текст**, который гость собирается отправить |
| Ошибка JS на сайте | тема 4 (аналитика/аварии) | текст ошибки, файл:строка, страница, браузер |
| Сайт не отвечает | тема 4 | какие URL и с каким кодом (проверка по расписанию) |
| Сводка за день | тема 4, 08:xx WITA | просмотры, заявки, из них WhatsApp, топ-5 страниц, топ источников |

Номера заявок сквозные и растут: счётчик в KV, формат `#0001`.

## Что нужно сделать один раз (5 минут, всё в панели Cloudflare)

### 1. Отозвать текущий токен и получить новый

@BotFather → `/revoke` → `@hostbali_bot`. Старый токен был отправлен в переписку,
считайте его публичным.

### 2. Добавить бота в чат

Бот должен быть **участником группы** и иметь право писать в темы, иначе
`sendMessage` вернёт 403. Права администратора достаточно.

### 3. Создать KV-хранилище (для номеров заявок и счётчиков)

Workers & Pages → **KV** → Create namespace → имя `THB_STATS` → скопировать
**Namespace ID** (он не секретный, его можно прислать мне).

### 4. Прописать переменные у воркера

Workers & Pages → `thebalihost` → Settings → **Variables and Secrets**:

| Тип | Имя | Значение |
|---|---|---|
| Secret | `TELEGRAM_TOKEN` | новый токен от BotFather |
| Text | `TG_CHAT` | `-1003961611036` |
| Text | `TG_TOPIC_LEADS` | `2` |
| Text | `TG_TOPIC_OPS` | `4` |

`TELEGRAM_TOKEN` обязательно **Secret**, не Text: секреты не показываются в
интерфейсе после сохранения и не попадают в логи.

### 5. Прислать мне Namespace ID

После этого я включаю воркер в `wrangler.jsonc` (`main`, привязка KV, cron) и
деплою. До этого момента сайт работает как обычная статика: код на страницах
уже стоит, но при отсутствии `/api/*` он тихо отключается и форма, как раньше,
уходит в WhatsApp — гость ничего не теряет.

## Конфигурация, которая будет добавлена в wrangler.jsonc

```jsonc
{
  "name": "thebalihost",
  "compatibility_date": "2026-07-28",
  "main": "worker/index.js",
  "assets": {
    "directory": "./",
    "binding": "ASSETS",
    "html_handling": "auto-trailing-slash",
    "not_found_handling": "404-page"
  },
  "kv_namespaces": [
    { "binding": "THB_STATS", "id": "<Namespace ID из шага 3>" }
  ],
  "triggers": { "crons": ["*/30 * * * *"] }
}
```

Cron раз в 30 минут: каждый запуск проверяет доступность трёх страниц, а в
08:xx WITA дополнительно присылает сводку за прошедшие сутки.

## Проверка после включения

```bash
curl -s https://thehostbali.com/api/health          # {"ok":true,...}
```

Затем на сайте: нажать WhatsApp → в теме 2 должна появиться заявка с номером.
Отправить форму BOOKING → вторая заявка, номер на единицу больше.

## Честные ограничения

- **Отправлено ли сообщение в WhatsApp — сайт не знает.** Мы фиксируем момент
  клика и текст, который подготовлен к отправке. Если гость закроет WhatsApp, не
  нажав «отправить», заявка всё равно придёт. Это скорее плюс: видно упущенных.
- Счётчик просмотров в KV — не замена GA4: он нужен для сводки в чате и не
  различает уникальных посетителей.
- KV может изредка потерять один инкремент при одновременных запросах. Для
  номеров заявок это означает теоретический пропуск номера, а не дубль.

## Команды в чате

Бот отвечает в той теме, где его спросили:

| Команда | Что вернёт |
|---|---|
| `/stats` | цифры за сегодня: просмотры, заявки, топ страниц, источники |
| `/stats вчера` | то же за прошедшие сутки |
| `/health` | доступны ли три ключевые страницы прямо сейчас |
| `/help` | список команд |

Автоматическая сводка за сутки приходит в тему 4 около 08:xx WITA — команды
нужны, когда хочется посмотреть раньше.

Webhook зарегистрирован на `https://thehostbali.com/api/tg` и защищён секретом
`TG_HOOK_SECRET`: запрос без него получает 403, поэтому подделать команду со
стороны нельзя.

## Откуда берутся цифры

Считает сам воркер: каждая страница отправляет анонимный пинг на `/api/hit`, из
него растут дневные счётчики в KV (просмотры, страницы, источники, заявки).
Куки не ставятся, IP не сохраняется.

Это **не замена GA4**: считаются просмотры, а не уникальные посетители, и нет
поведенческих метрик. Зато работает без внешних ключей и доступов.

### Если нужны настоящие данные GA4 в чате

Тогда нужен доступ к Google Analytics Data API, и от вас потребуется:

1. Google Cloud → создать проект → включить **Google Analytics Data API**.
2. Создать **service account** → выпустить JSON-ключ.
3. В GA4: Admin → Property access management → добавить e-mail этого
   service account с ролью **Viewer**.
4. Прислать: JSON-ключ (я положу в секрет Cloudflare) и **Property ID** —
   число из GA4 Admin → Property details, не `G-...`.

После этого сводка сможет показывать пользователей, сеансы, источники,
конверсии `whatsapp_click` и `booking_submit` — ровно как в интерфейсе GA4.
