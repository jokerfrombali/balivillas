# Прямые бронирования: связка сайта с Hostfully и приём оплаты — план и статус

Этот файл — техническое задание и журнал состояния для связки thehostbali.com с Hostfully PMP (календарь, бронь) и способом приёма оплаты (Flywire или ручной перевод). Секретных значений здесь нет — только имена переменных и место, где они хранятся, по тому же правилу, что и в `docs/PROJECT-STATE.md`.

Обновлено: 25.08.2026.

## Зачем это нужно

Сейчас `POST /api/lead` (см. `worker/index.js`) — это не бронирование, а заявка: форма на сайте или клик по WhatsApp собирает данные гостя и шлёт их текстом в Telegram-тему «заявки». Поле `villa` — свободный текст, доступность дат нигде не проверяется, оплата не фиксируется нигде, кроме головы менеджера. Гость может отправить заявку на даты, которые уже заняты.

Цель — чтобы бронирование с сайта: (1) показывало гостю реально свободные даты и цену из Hostfully, а не «наугад»; (2) на время оплаты придерживало даты в Hostfully, чтобы их не увели Airbnb/Booking или другой гость; (3) после оплаты становилось подтверждённой бронью в Hostfully с записанным платежом — Telegram-уведомление при этом остаётся, но как уведомление, а не как единственная запись о брони.

## Архитектура связки под наш стек

Сайт — статика на Cloudflare Workers, backend — один файл `worker/index.js` с ручным роутингом по `url.pathname`, без базы данных: состояние живёт в KV (`THB_STATS`). Значит календарь Hostfully кэшируем тоже в KV, а не поднимаем отдельную БД.

Новые эндпоинты в `worker/index.js`, тем же стилем, что уже есть (`json()`, `tg()`, `bump()`, `tooFast()`):

- `GET /api/availability?villa=<slug>&from=&to=` — отдаёт из KV-зеркала занятые даты по вилле. Сайт красит календарь этим, а не дёргает Hostfully на каждый визит.
- - `POST /api/quote` — проксирует `POST /quotes` в Hostfully (цена, только оттуда, никаких своих расчётов).
  - - `POST /api/booking/hold` — создаёт лид (`POST /leads`, статус `NEW`) и сразу `POST /leads/{uid}/put-on-hold`: даты закрываются на 24 часа (срок регулируется в Hostfully → Rental Conditions → Hold Duration), пока гость платит.
    - - `POST /api/booking/confirm` — вызывается после подтверждения оплаты: `POST /leads/{uid}/mark-as-booked` + `POST /transactions` с `manual: true` (оплата принята вне Hostfully — то есть годится и для Flywire, и для перевода на счёт).
      - - `POST /api/hostfully/webhook` — принимает `NEW_BOOKING`, `BOOKING_UPDATED`, `BOOKING_CANCELLED`, `NEW_BLOCKED_DATES`, `PROPERTY_AVAILABILITY_UPDATED`; телу не доверяем (подписи в вебхуках Hostfully нет), по `lead_uid`/`property_uid` перезапрашиваем сущность через API и обновляем KV-зеркало. Существующий `/api/lead` из Telegram-уведомлений никуда не девается — вызывается параллельно, как и сейчас.
       
        - Секреты — по той же схеме, что `TELEGRAM_TOKEN` и `GA_SA_KEY`: только в Cloudflare → Workers → thebalihost → Variables, в репозитории — только имена.
       
        - | Переменная | Что | Где взять |
        - |---|---|---|
        - | `HOSTFULLY_API_KEY` | ключ API | Hostfully → Настройки агентства → Agency Settings, появится после включения API access |
        - | `HOSTFULLY_AGENCY_UID` | не секрет, но фиксируем тут | `a0a2a370-4c6a-4f90-95d7-b2a2bbe0584a` |
        - | `HOSTFULLY_BASE_URL` | sandbox/prod | `https://sandbox-api.hostfully.com/api/v3.3` на время разработки |
        - | `FLYWIRE_*` | ключи процессора, если выбрали Flywire | появятся после ответа их sales-команды |
       
        - ## Привязка вилл
       
        - В `data/villas.json` у каждой из 12 вилл (`id`, `slug`) нужно добавить `hostfullyPropertyUid`. Список UID объектов Hostfully снимается разовым скриптом (`GET /properties?agencyUid=...`) после получения API-ключа — вручную сверяется по названию с villas.json, один раз.
       
        - ## Что решить владельцу перед стартом кода
       
        - 1. Отправить запрос на API-доступ на `api@hostfully.com` — текст согласован, ждёт отправки.
          2. 2. Способ оплаты: Flywire (форма на flywire.com подготовлена, не отправлена) или ручной перевод/счёт — от этого зависит, что стоит в `manual` при записи транзакции и нужен ли вообще процессор.
             3. 3. Депозит/график: в Hostfully уже настроено 50% при брони + остаток за 45 дней (Rental Conditions) — `POST /api/booking/confirm` в первой версии пишет один платёж; под график нужно два вызова и напоминание про второй.
                4. 4. Пока Airbnb/Booking не подключены в Hostfully как каналы — hold защищает даты только внутри Hostfully. Канал может продать те же даты, не зная про hold. Решается либо подключением каналов, либо ручным контролем на переходный период.
                  
                   5. ## Порядок работ, когда все решения приняты
                  
                   6. 1. Получить API-ключ, положить в Cloudflare Variables.
                      2. 2. Разовый скрипт: снять UID объектов, прописать `hostfullyPropertyUid` в `data/villas.json`.
                         3. 3. Добавить пять эндпоинтов в `worker/index.js` + KV-зеркало календаря + cron-обновление (уже есть `scheduled()` в файле — туда же).
                            4. 4. Зарегистрировать вебхуки на `https://thehostbali.com/api/hostfully/webhook`.
                               5. 5. Прогнать один тестовый цикл на sandbox: hold → confirm → проверить бронь и транзакцию в Hostfully.
                                  6. 6. Только после этого просить Hostfully включить production.
