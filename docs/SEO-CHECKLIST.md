### Подтверждение профиля: видео и фото офиса

Google подтверждает профиль одним видео **без монтажа** (30 сек — 5 мин), снятым
на телефон на месте. Показать надо три вещи подряд, не выключая камеру:

1. **Где это.** Улица, вывеска или табличка с названием, номер дома, соседние
   ориентиры — чтобы точка на карте совпала с реальностью.
2. **Что внутри.** Вход, рабочее место, техника, папки, брендированные вещи —
   всё, что показывает: тут работают, а не просто жилой дом.
3. **Что вы этим управляете.** Ключи от вилл с бирками, открытая система
   бронирований на экране, договоры или документы с названием BaliVillas,
   визитки. Это главный пункт: Google проверяет право управления, а не красоту.

Чужие лица в кадр лучше не брать. Если офис — по сути рабочее место без вывески,
снимайте по пункту 3 и добавьте кадр с ключами и хозяйственным набором для вилл.

Альтернатива: вернуться на шаг «клиенты могут прийти по адресу» и ответить
«нет» — тогда профиль становится service-area, адрес не публикуется, а видео
снимается про инструменты работы, а не про помещение.

## 5. www -> apex (сделано 26.08.2026)

Cloudflare → balivillas.ai → Rules → Redirect Rules, правило
«Redirect from WWW to root» из шаблона:
- Wildcard pattern, Request URL `https://www.*`
- Target URL `https://${1}`, статус **301**
- **Preserve query string включён** — в шаблоне он выключен по умолчанию, и без
  него на редиректе терялись бы метки вроде `?utm_source=chatgpt.com`, то есть
  ломалась бы атрибуция в GA4.

В воркере это сделать нельзя: HTML отдаётся напрямую из хранилища статики и до
кода воркера не доходит — редирект там просто не сработал бы.

При деплое Cloudflare предупреждает «This rule may not apply to your traffic —
DNS may not be proxying www». Предупреждение ложное: www проксируется, правило
работает. Проверено — ровно один прыжок, петель нет, query string сохраняется:

```bash
curl -s -o /dev/null -w "%{http_code} -> %{redirect_url}
" "https://www.balivillas.ai/?utm_source=chatgpt.com"
```

Мелочь: `www/robots.txt` отдаётся напрямую, без редиректа — Cloudflare
подмешивает свой managed-блок раньше правила. Вреда нет: содержимое то же, а все
карты сайта внутри указывают на apex.

## ИИ-краулеры: открыты, и это осознанно (09.09.2026)

Проект нацелен на видимость в ИИ-ассистентах, поэтому на сайт пускаются все
ИИ-краулеры. До 09.09.2026 это было не так, и `llms.txt` с `llms-full.txt`
писались фактически впустую: Cloudflare блокировал тех, для кого они сделаны.

Что было и что стало:

| Настройка Cloudflare | Было | Стало |
|---|---|---|
| Security → Settings → Bot traffic → **Block AI bots** | «Block only on pages with ads», плюс с 15.09 в блок попадали смешанные краулеры | **Do not block (allow crawlers)**, смешанные краулеры разрешены |
| AI Crawl Control → Signals → **Managed robots.txt** | включён, дописывал поверх нашего файла блок `Disallow: /` для GPTBot, ClaudeBot, Google-Extended, CCBot, Bytespider и других | выключен |
| AI Crawl Control → Security | 15 краулеров в блоке | 0 |

`robots.txt` теперь отдаётся наш собственный, 848 байт, с явным `Allow: /` для
GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-Web, PerplexityBot,
Google-Extended, Applebot-Extended и прочих.

Проверка снаружи (curl с соответствующим User-Agent) — 200 у GPTBot, ClaudeBot,
PerplexityBot, CCBot и Googlebot, включая `/llms-full.txt`.

**Важно:** это настройки дашборда Cloudflare, из репозитория их не изменить.
Что бы ни лежало в нашем `robots.txt`, включённый Managed robots.txt допишет
своё сверху. Если однажды ИИ-ассистенты перестанут видеть сайт — проверять
надо в первую очередь эти три места, а не файл в репозитории.
